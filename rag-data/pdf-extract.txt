## 5. 주요 기능 
### KWS (openWakeWord)

'교통봇' 호출어를 감지하면 다음 동작으로 넘어갑니다.

- 직접 녹음한 200개의 호출어 데이터를 기반으로 데이터 증강을 수행하여 약 1000개의 학습 데이터를 구축했습니다.
- openWakeWord 모델을 파인튜닝하여 호출어 인식 성능을 향상했습니다.
- 오탐을 줄이기 위해 유사 발음 단어들을 네거티브 데이터로 추가 학습했습니다.
- 연속 4회 감지 방식으로 안정성을 높였습니다.
- 호출어 감지 score 0.97을 달성했습니다.


### STT (Whisper-Base) + 공공데이터포털 OpenAPI

호출어 감지 후 사용자 음성을 텍스트로 변환하고, 광주광역시 BIS API를 활용해 실시간 버스 도착 정보를 안내합니다.

- 사용자 질문에서 버스 번호와 정류소 이름을 추출합니다.
- Levenshtein Ratio 유사도 비교를 적용하여 정류소명을 잘못 인식해도 유사한 정류소를 탐색할 수 있도록 구현했습니다.
- 동일한 이름의 정류소가 상행·하행으로 나뉘는 경우를 고려하여 정류소(종점) 형태로 안내합니다.


### TTS (GPT-SoVITS-v2Pro)

생성된 답변을 신뢰감 있는 여성 아나운서 스타일 음성으로 출력합니다.

- 자연스러운 한국어 발화와 추론 속도의 균형을 고려해 GPT-SoVITS-v2Pro를 사용했습니다.
- API 서버를 도입해 모델을 메모리에 상주시켜 즉시 추론 가능하도록 최적화했습니다.
- 로컬 추론 시 약 20초 소요되던 응답 시간을 API 서버 도입 후 1~3초 수준으로 단축했습니다.
- Cloudflare Tunnel을 활용해 외부 환경에서도 API 서버에 접근 가능하도록 구성했습니다.

## 9. 트러블 슈팅

### 김현진
#### KWS - 호출어 오탐 문제
| 문제 | 해결 | 결과 |
|---|---|---| 
| 일상 대화 중 유사 발음을 호출어로 잘못 인식하는 오탐 현상 발생 | 유사 발음 단어들을 네거티브 데이터로 추가 학습하고, 연속 4회 감지 방식을 적용하여 안정성 개선 | 호출어 감지 정확도 향상 및 오탐 감소 |

### 문서현
#### STT - 정류소명 인식 오류 문제
| 문제 | 해결 | 결과 |
|---|---|---| 
| Whisper 음성 인식 과정에서 정류소명이 완전히 일치하지 않는 경우 발생 | Levenshtein Ratio 기반 문자열 유사도 비교를 적용하여 유사한 정류소명을 탐색하도록 구현 | 잘못 인식된 정류소명에도 가장 유사한 정류소를 탐색할 수 있도록 개선 |

### 김가람
#### TTS - TTS 응답 지연 문제
| 문제 | 해결 | 결과 |
|---|---|---| 
| 로컬 환경에서 GPT-SoVITS 추론 시 응답까지 약 20초 소요 | API 서버를 통해 모델을 메모리에 상주시켜 재로딩 없이 추론 가능하도록 개선 | 응답 시간을 1~3초 수준으로 단축 |

## 10. 프로젝트 회고
- 김현진 :
> 이번 프로젝트에서 KWS를 담당하면서 파인튜닝이 단순한 학습 반복이 아니라는 걸 깨달았습니다.
>
> 처음에는 모델만 잘 고르면 된다고 생각했는데,
> 막상 해보니 어떤 데이터를 얼마나 구성하느냐가 성능을 결정한다는 걸 직접 느꼈습니다.
>
> "교통안내"에서 "교통봇"으로 호출어를 바꾸는 과정도 쉽지 않았습니다.
> 단순히 이름을 바꾸는 게 아니라 데이터를 다시 녹음하고,
> 오탐을 유발하는 유사 단어들을 네거티브 데이터로 추가해 재학습을 반복해야 했습니다.
> 처음부터 오탐 가능성을 고려해서 호출어를 설계했어야 한다는 아쉬움이 남았지만,
> 그 과정에서 문제를 발견하고 스스로 해결해나가는 경험이 더 값졌습니다.
>
> 또한 팀원들과 협업하면서 각자 개발한 기능을 하나로 연결하는 과정이 생각보다 쉽지 않았습니다.
> 
> 서로 구조가 달라 맞추는 데 시간이 걸렸고,
> 처음부터 입출력 형식을 함께 정해놓고 시작하는 것이 얼마나 중요한지 깨달았습니다.
>
> 그래도 각자 만든 기능이 하나로 연결되어 실제로 동작하는 순간은
>
> 이번 프로젝트에서 가장 뿌듯하고 기억에 남는 순간이었습니다.
> 다음에는 더 다양한 환경에서도 안정적으로 동작하는 모델을 만들어보고 싶습니다.

- 문서현 :  
>  이번 프로젝트를 통해 KWS, STT, TTS를 하나의 파이프라인으로 연결하며  
>  음성 AI 서비스의 전체 흐름을 경험할 수 있었습니다.  
>  
>  특히 Whisper 기반 음성 인식 과정에서 정류소명이 정확히 인식되지 않는 문제를 해결하기 위해  
>  Levenshtein Ratio 기반 문자열 유사도 비교를 적용하며  
>  실제 사용자 환경을 고려한 예외 처리의 중요성을 배울 수 있었습니다.  
>  
>  그리고 협업 과정에서는 GitHub를 활용한 버전 관리와 역할 분담의 중요성을 경험했습니다.  
>  
>  다만 실제 다양한 소음 환경에서 충분한 테스트를 진행하지 못한 점은 아쉬움으로 남았습니다.  
>  향후에는 GPU 환경 최적화와 모바일 환경 지원,  
>  다양한 지역의 BIS API 연동 등을 통해 서비스를 확장해보고 싶습니다.  

- 김가람 :  
>  저는 본 프로젝트를 통해서 배운게 많은 거 같습니다.  
>  먼저 하나의 파이프라인으로 연결하는것을 통해 서비스의 워크플로우가 어떻게 이어지는가에 대한 통찰을 얻게 되었습니다.  
>  특히 오케스트레이터를 통해서 조율되는 워크플로우가 있음도 알게 되었습니다.    
>    
>  두번쨰로 tts를 맡으면서 추론과정속에서 아키텍처를 어떻게 최적화 할 수 있는지에 대한 고민을 한 것이 정말 중요한 경험이었다고 생각합니다.  
>  api를 통해서 모델 메모리 상주방식을 설계하고 응답지연문제를 획기적으로 줄인 경험은 훗날 크게 도움될거라 확신합니다.  
>    
>  마지막으로 혼자가 아닌 팀프로젝트로 팀원들과  GitHub를 통한 협업방식이 처음에는 낯설었지만 점차 시너지 효과가 있음을 알게되는 유익한 시간이였습니다.
